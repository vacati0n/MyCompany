# Architecture Decision Record D-008

## Metadata

- ADR ID: D-008
- Title: A seventh resource makes the gate position mandatory and gate transitions write-once, and the sixth resource's header is corrected in place
- Date: 2026-10-09
- Status: Proposed
- Owners: omn-tech-lead as the accepting owner of the Design Gate under the producer exclusion rule; architect as the producing agent
- Related Work Items: MC-8; technical design package DESIGN-2026-0008; planner tasks T-009, T-021 and T-034; sequencing constraints P-001 and P-013

## Context

- Problem statement: the sixth resource's header says no delivered table is altered and only the chain-head row is written, while it adds and back-fills an order column whose loss on reversal it does not state, and the column admits nulls and the record admits updates, so a transition can lose its position.
- Business and technical constraints: C-016 keeps every change additive and existing rows meaningful; C-003 keeps every check binding every writer; C-011 depends on the position deciding the latest state.
- Current architecture baseline: F-029 records the column, sequence, back-fill, index and trigger and the missing update refusal; F-032 records that the installer reruns every resource and keeps no applied-resource record.

## Decision

- Selected option: O-002.
- Decision statement: the sixth resource's header text is corrected to state that it adds and back-fills the order column and that reversing it loses ordering once a later transition exists, with no statement changed; the seventh resource makes the position mandatory, validating every existing row, and refuses any update or delete of a gate transition; it does not touch the sequence, so the carried re-application hazard is not widened.
- Scope of impact: M-001 carries both.

## Alternatives Considered

1. O-011, adding the position rule inside the sixth resource.
- Benefits: one resource holds the whole position design.
- Risks: a store re-installing runs a changed applied resource.
- Why not selected: it ties on impact surface and reuse and loses on migration burden.

2. O-001, O-003, O-004, O-005, O-006, O-007, O-008, O-009 and O-010, the other options of the package evaluation.
- Benefits: each carries this decision unchanged.
- Risks: each differs from O-002 in another design area only.
- Why not selected: none is decided on this record.

## Consequences

- Positive outcomes expected: no writer can commit or leave a transition without a position; an operator reversing the sixth resource is warned.
- Tradeoffs accepted: a store holding a position-less transition refuses the seventh resource until the operator decides.
- Risks introduced: R-018, a failing application; R-019, re-application; R-027, a delivered updater; R-034, a populated store.

## Validation Plan

- Metrics to monitor:
  - The count of gate transitions without a position; the expected value is zero.
  - The count of updated or deleted gate transitions; the expected value is zero.
  - The count of sequence changes made by the seventh resource; the expected value is zero.
- Verification checkpoints:
  - Inspection of the sixth resource's header.
  - A direct write without a position refused in a throwaway store.
- Rollback or reversal conditions:
  - Reversed by dropping the mandatory rule and the write-once check, each without loss.
