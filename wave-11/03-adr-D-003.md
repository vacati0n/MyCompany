# Architecture Decision Record D-003

## Metadata

- ADR ID: D-003
- Title: The installed renderer, browser, font and Node are verified from the manifests with a no-extra-file check and held from Design's start to its last render
- Date: at emission in run-9d83536ecd16
- Status: Proposed
- Owners: architect (producer); omn-tech-lead (accepting owner of the Design Gate)
- Related Work Items: MC-12; the supplied execution plan's design tasks

## Context

- Problem statement: The decision record hashes four files directly while a render loads about 15,000 (F-019); a file could change between verification and load.
- Business and technical constraints: C-004, C-005, C-008.
- Current architecture baseline: F-010, F-019, F-027.

## Decision

- Selected option: O-001
- Decision statement: RendererInstallationVerifier hashes each manifest against its configured expected value, verifies every listed file, and refuses absolute or climbing entries and unlisted files under the verified folders; Node is one expected file; identities are read from verified bytes (package metadata, executable version resource, face name table); at Design's start every verified file, staged input and bundle file is opened read-only, hashed through its handle and held until the last render exits.
- Scope of impact: M-008, M-014, M-025.

## Alternatives Considered

1. O-012: Check the four directly recorded hashes once at start
- Benefits: Fast
- Risks: Most loaded files unhashed and unheld
- Why not selected: Eliminated: violates C-004

## Consequences

- Positive outcomes expected: The hashes recorded name the bytes that ran; a planted module or a re-created cache is refused.
- Tradeoffs accepted: About 665 MB hashed and about 15,120 handles held per Design start, unmeasured.
- Risks introduced: R-003, R-018, R-022

## Validation Plan

- Metrics to monitor: Files verified per manifest; observed hashing time; refusals on a swapped or extra fixture file.
- Verification checkpoints: Fixture tests in P-006; the swap round trip in P-019.
- Rollback or reversal conditions: A render loads a file whose recorded hash differs from its bytes.
