# Architecture Decision Record D-002

## Metadata

- ADR ID: D-002
- Title: Bundle and render run as Node invocations of the repository's render script through the one starter, confined to staging, in a kill-on-close job
- Date: at emission in run-9d83536ecd16
- Status: Proposed
- Owners: architect (producer); omn-tech-lead (accepting owner of the Design Gate)
- Related Work Items: MC-12; the supplied execution plan's design tasks

## Context

- Problem statement: The approved renderer runs as Node with a browser and a compositor, each able to write outside the output root, fetch a browser, send a usage event or outlive its parent (F-020, F-021, F-022, F-023).
- Business and technical constraints: C-005, C-006, C-007, C-008, C-017.
- Current architecture baseline: F-001, F-002, F-003, F-020, F-021, F-022, F-023, F-025.

## Decision

- Selected option: O-001
- Decision statement: ExternalMediaTool realises IGraphicRenderer: it starts the configured Node with the staged render script, a mode and a request file only, working in the graphics staging folder, with a cleared environment pointing every temporary and profile folder into staging, assigns the process to a kill-on-close job before writing its start line, and closes the job past the bound, on cancellation and after exit; the render script loads only the anchored bundler and renderer, disables caching, keeps root, output and public folders in staging, always passes the verified browser path, calls only the frame render function and never passes a licence key.
- Scope of impact: M-002, M-003, M-004, M-015, M-018.

## Alternatives Considered

1. O-010: Bundler and browser with their defaults
- Benefits: Matches the trial
- Risks: Cache under the installed packages; profile in the system temporary folder
- Why not selected: Eliminated: violates C-005

2. O-011: One process renders all graphics under one bound
- Benefits: Fewer starts
- Risks: No bound per graphic; one failure ends all
- Why not selected: Eliminated: violates C-006

3. O-013: The delivered whole-tree kill only
- Benefits: No native call
- Risks: A browser whose parent exited survives
- Why not selected: Eliminated: violates C-006

## Consequences

- Positive outcomes expected: Every process of a render ends with its job; every write lands under the output root; no browser fetch or usage event is reachable.
- Tradeoffs accepted: A declared native call for the job; confinement rests on A-002, A-003, A-005 and A-006 until proven.
- Risks introduced: R-001, R-002, R-004, R-005, R-009, R-023

## Validation Plan

- Metrics to monitor: Processes remaining after each render; files outside staging before and after; installed manifests before and after.
- Verification checkpoints: Stand-in tests in P-007; the first graphic's evidence in P-018; process and network evidence in P-019.
- Rollback or reversal conditions: A process of a render survives its job, or a file is written outside the run's staging folder.
