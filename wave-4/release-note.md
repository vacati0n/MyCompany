## Highlights

- Feature additions: an analytics surface over the company's own records in which every quantity resolves to exactly one of three states — an observed value, an observed zero, or unmeasured — with the unmeasured case carrying no value field, so a quantity nobody observed cannot be rendered as a number anywhere and an unmeasured reading names which of two closed reasons applies (IR-2026-0005, `C-001`, `C-002`, exercised by `T-001`, `T-003`, `T-024`, `T-025`). Cost is readable per produced item and per calendar period from recorded operations, with the aggregation left in the datastore's exact decimal type and the count of records aggregated stated (`C-005`, `C-006`, `T-028`). The six revenue-derived figures — revenue, revenue per thousand views, profit per video, profit per channel, return on investment and cost per dollar of revenue — are declared as deferred measures carrying no value field and are visible in no view, reachable only through an admission function that requires an observed revenue parameter recorded with its source observation and that observation's date (`C-007`, `C-010`, `T-004`, `T-023`, `T-036`); no such parameter is recorded, and none of the six shows a value. Composers exist for approval effort as three separate components, for all twelve production-path stage outcomes including every refusal, for supply-audit results and for compliance determinations; **four of those five record sources have no table, no adapter and no production caller, so they cannot be reached from the composed system and are exercised only against constructed records** (`K-001`). **Nothing publishes and nothing was made publishable**: IR-2026-0005 records no upload path, channel creation, account creation, purchase, subscription session or render added, the five structural absences on the upload path unchanged and none of them made a configuration value, the three coded preconditions still encoded and undischarged with an unknown state folding to not-satisfied while staying visible in the refusal, and owner approval still a state in the gate transition table and absent from configuration (`T-018`, `T-020`).
- Bug fixes: a calendar period in which no operation was recorded used to read as a zero amount, indistinguishable from a period whose recorded operations aggregate to zero; the parallel three-state reading returns unmeasured for the first and an observed zero for the second, and IR-2026-0005 records both readings asserted side by side against the datastore in `T-027` and `T-014`. The defects corrected inside this change before it left the run — the register write that stored an observed zero as an absence, the boundary assertions that nothing started, and four gaps in the member rule — are corrections to this change's own first delivery rather than fixes to behaviour a reader was running, and they are recorded under Test status and in the Known Issues register rather than presented as fixes.
- Improvements: the boundary assertions now run as part of every **solution** build and fail it, where they previously sat in a project nothing started, and RP-2026-0002 confirms by execution that the target fires on every solution build including one where nothing had changed, reporting forty-six assertions passing, that a named property suppresses it visibly, that the runner exits non-zero on an aborted run, and that the task carries neither continue-on-error nor ignore-exit-code. **The refusal this buys is qualified and the qualification travels with it**: a model-dependent project reference that is *used* fails the build; one *declared and never used* does not, because the assertions read the references the compiler retained rather than those the project file declares, and building a single project rather than the solution does not start the assertions at all (`K-002`, `K-005`, `K-006`).
