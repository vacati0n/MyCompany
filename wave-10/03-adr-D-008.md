# Architecture Decision Record D-008

## Metadata

- ADR ID: D-008
- Title: Provenance read from the verified files, a repeat check on the first part and no quality rating
- Date: at emission in run-dfcae1756c32
- Status: Proposed
- Owners: architect (producer); omn-tech-lead (accepting owner of the Design Gate)
- Related Work Items: MC-11; the supplied execution plan's design tasks

## Context

- Problem statement: Every model-produced file must carry provenance and an observed repeatability statement, never a claim.
- Business and technical constraints: C-003, C-008, C-016.
- Current architecture baseline: F-029, F-030, F-031, F-034.

## Decision

- Selected option: O-001
- Decision statement: Each model part records name, version and code licence from the package metadata, the voice from its configuration, the dataset licence from the model card, weights and voice licence as not stated, the six settings beside the voice's defaults, the five hashes from the held handles, the argument list and the repeatability statement from a second generation of the first part; no quality rating.
- Scope of impact: M-001, M-005, M-014.

## Alternatives Considered

1. O-005: Expected hashes written to the store by an installation command
- Benefits: Hashes travel with the store
- Risks: A store write before the go
- Why not selected: Eliminated: violates C-009

2. O-007: The runtime's console launcher with the inherited environment
- Benefits: The runtime's own entry point
- Risks: Inherited interpreter variables may redirect the code that runs
- Why not selected: Ties on hard constraints and impact; loses on reuse

## Consequences

- Positive outcomes expected: Provenance contradicts nothing loaded and claims no repetition unseen.
- Tradeoffs accepted: Two licence fields read not stated; the first part costs a second generation.
- Risks introduced: R-007, R-013, R-019

## Validation Plan

- Metrics to monitor: Every provenance field non-empty for every model part.
- Verification checkpoints: Deterministic and non-deterministic stand-ins in P-012.
- Rollback or reversal conditions: A repeatability statement recorded without its comparison.

- Tech Lead: unsigned; acceptance belongs to the Design Gate
- Product Owner (if scope-impacting): unsigned
