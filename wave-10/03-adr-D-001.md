# Architecture Decision Record D-001

## Metadata

- ADR ID: D-001
- Title: A closed four-member narration source set and one pure selection rule, re-derived before every part
- Date: at emission in run-dfcae1756c32
- Status: Proposed
- Owners: architect (producer); omn-tech-lead (accepting owner of the Design Gate)
- Related Work Items: MC-11; the supplied execution plan's design tasks

## Context

- Problem statement: Nothing chooses a narration source; the produce service narrates every producing mode through the capability boundary.
- Business and technical constraints: C-001, C-002, C-008.
- Current architecture baseline: F-001, F-002, F-010.

## Decision

- Selected option: O-001
- Decision statement: NarrationSource has exactly four members; a pure rule in the rule-determined assembly reads mode, designation, the latest registration's state and the model's verification state, prints one line per part with its reason, and is re-derived before every part, stopping the run before a part whose source would differ.
- Scope of impact: M-001, M-002, M-005.

## Alternatives Considered

1. O-002: Model process started by a sibling type
- Benefits: The model's invocation sits apart from the media tool
- Risks: Duplicates the delivered bound and process-tree termination; widens the one-starter assertion
- Why not selected: Ties on hard constraints and impact; loses on reuse

2. O-003: Vendor bar as a settings value
- Benefits: One switch for every source
- Risks: A settings edit re-admits the vendor
- Why not selected: Eliminated: violates C-002

3. O-007: The runtime's console launcher with the inherited environment
- Benefits: The runtime's own entry point
- Risks: Inherited interpreter variables may redirect the code that runs
- Why not selected: Ties on hard constraints and impact; loses on reuse

## Consequences

- Positive outcomes expected: Every part's source is visible before anything runs and equals the recorded provenance.
- Tradeoffs accepted: A registration recorded mid-run stops a model run part-way.
- Risks introduced: R-012

## Validation Plan

- Metrics to monitor: Equal per-part lines over two plan-only runs; planned source equal to every artifact's recorded source.
- Verification checkpoints: Rule table tests and the plan-versus-provenance round trip in P-004 and P-012.
- Rollback or reversal conditions: A source recorded for a part differs from the planned one without the run stopping.
