# Architecture Decision Record D-006

## Metadata

- ADR ID: D-006
- Title: Installation verification from settings: five files and the runtime's RECORD entries, hashed through held handles
- Date: at emission in run-dfcae1756c32
- Status: Proposed
- Owners: architect (producer); omn-tech-lead (accepting owner of the Design Gate)
- Related Work Items: MC-11; the supplied execution plan's design tasks

## Context

- Problem statement: The model may be used only when its installed files are the approved ones, and the hash must name the bytes loaded.
- Business and technical constraints: C-003, C-009, C-010.
- Current architecture baseline: F-028, F-031, F-032, F-033.

## Decision

- Selected option: O-001
- Decision statement: The settings name five files and their expected hashes; the verifier refuses a configuration path other than the model path plus .json, any file inside the repository, a missing or differing file, and any RECORD entry mismatch; before each part it hashes through handles denying write and delete that it holds until the process exits; plan-only verifies without a process.
- Scope of impact: M-004, M-007, M-008.

## Alternatives Considered

1. O-005: Expected hashes written to the store by an installation command
- Benefits: Hashes travel with the store
- Risks: A store write before the go
- Why not selected: Eliminated: violates C-009

2. O-007: The runtime's console launcher with the inherited environment
- Benefits: The runtime's own entry point
- Risks: Inherited interpreter variables may redirect the code that runs
- Why not selected: Ties on hard constraints and impact; loses on reuse

## Consequences

- Positive outcomes expected: Provenance names the files that loaded, read from those files.
- Tradeoffs accepted: The base interpreter and the dependencies' code are verified only if extended.
- Risks introduced: R-002, R-003, R-021

## Validation Plan

- Metrics to monitor: Each part's recorded hashes equal the expected values.
- Verification checkpoints: Swap tests before verification, during a held run and between parts in P-010 and P-019.
- Rollback or reversal conditions: A part generated from a file whose hash differs from the recorded one.
