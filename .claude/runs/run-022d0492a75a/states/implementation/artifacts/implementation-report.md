## Implementation Summary

- Change intent: A non-technical operator can now make one pilot video without editing JSON or typing a command line. The new local web app, MediaCompany.Pilot.Web, shows every screen in plain Vietnamese and walks the operator through seven steps. (1) A fact sheet form with a live banned-term check that names the term and its class. (2) The three images. (3) The script, with a tick for each sentence's source line. (4) Recording in the browser, with a 60 s hard stop, a timer, playback and re-record; upload is still possible. (5) The portrait presenter clip, length within 0.5 s. (6) Produce, with progress and a manual timing editor. (7) Preview, the kit 04 checklist (B3 and B5 included), and approval by hash. A first-run setup screen writes the settings. It can create a desktop shortcut if the operator agrees.
- Approach taken: The app is its own assembly on the web SDK and the installed ASP.NET Core shared framework, with zero package references. The pages are plain HTML, CSS and JavaScript embedded in the assembly; recording uses MediaRecorder; no script, font or style is fetched. It listens on 127.0.0.1 only and checks at start-up that every bound address is 127.0.0.1. Every request must name the exact host. Every state-changing request must carry the exact Origin and a token that is new at each start. Pure checks, settings validation, probe, recording conversion and recording admission run in process through the toolchain library. check, script, produce, approve and verify run as the toolchain executable in a child process: an argument list, no shell, a kill-on-close job, and the digest recorded at setup. The operator sees the toolchain's own line unchanged. For the fourteen codes in the guide, the app adds the guide's Vietnamese reason and next step. The tool keeps every decision: hash approval, the 60 s limit, the reused-recording refusal, the safe area, banned terms, the 0.5 s clip tolerance and the 1.2 s caption page. The app adds pre-checks only in front of those decisions. Necessity and reuse: The new project exists because the Design Gate requires the app to be an assembly the toolchain never references. Every check the app shows reuses the toolchain's own code (held data, fact sheet check, admission, ledger, settings reader, media tool) rather than a copy. The new test program exists because the decision requires zero package references, which the MC-16 xunit project cannot meet. It reuses the MC-16 fixture helpers by link, and its address harness is the MC-16 job-membership harness with the address columns kept. No package and no new framework dependency was added.
- Design reference: technical-design.md decisions D-001 to D-015 and delivery steps P-001 to P-013; Scope Gate decision record entry 1310; Design Gate decision record entry 1311.
- Out of scope: src/MediaCompany.Pilot is unchanged, along with its tests, the MC-16 kit and guide files, MC-13 and MC-14 material, and the company store database. Docker stayed down. Nothing was signed in to, created, bought, published or downloaded. No generative model, speech recognition, text-to-speech or voice cloning is used.
