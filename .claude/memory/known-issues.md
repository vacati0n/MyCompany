# Memory: Known Issues

## Purpose

Persist active defects, recurring failure patterns, risk notes, and mitigation status.

## Structure

- Issue ID:
- Symptom summary:
- Impact level:
- Current mitigation:
- Root-cause status:
- Long-term fix owner:
- Next review date:

## Ownership

- Primary Owner: QA
- Approver: Tech Lead
- Contributors: Bug Analyst, Implementer, Documentation

## Update Rules

- Add issue only when supported by reproducible evidence.
- Update after each triage, fix attempt, and verification cycle.
- Include clear status transitions (open, mitigated, resolved).
- Keep mitigation and risk statements current.

## Consumers

- Bug Analyst for diagnosis continuity.
- QA for regression planning.
- Orchestrator and Tech Lead for release risk decisions.

## Lifecycle

- Open when issue is validated.
- Mitigated when temporary containment exists.
- Resolved when fix is verified.
- Archived after sustained post-release stability.
