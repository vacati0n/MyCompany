# Memory: Coding Standard

## Purpose

Persist coding conventions that ensure maintainable, consistent, and reviewable code across teams.

## Structure

- Standard ID
- Rule statement
- Scope (backend, frontend, shared)
- Example and counterexample
- Enforcement mechanism (review, analyzer, test)
- Last reviewed date

## Ownership

- Primary Owner: Tech Lead
- Approver: Reviewer
- Contributors: Backend Developer, Frontend Developer, QA

## Update Rules

- Update when standards are adopted or revised by engineering governance.
- Include migration guidance for breaking standard changes.
- Link related style, lint, and quality gates.
- Revalidate standards quarterly.

## Consumers

- Implementers for coding decisions.
- Reviewers for compliance checks.
- QA for verification strategy alignment.

## Lifecycle

- Draft during standards proposal.
- Active after technical approval.
- Deprecated when replaced by a newer standard.
- Archived for historical reference and audits.
