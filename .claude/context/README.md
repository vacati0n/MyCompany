# Context Specification

## Purpose

Define the authoritative baseline for product, technical, and release decisions.

## Responsibilities

- Capture current product goals, scope boundaries, and acceptance intent.
- Capture architecture constraints, stack policies, and integration assumptions.
- Capture release cadence, risk posture, and readiness expectations.
- Eliminate conflicting assumptions before workflow execution.

## Loading Order

1. `product-context.md`
2. `technical-context.md`
3. `release-context.md`
4. `context-map.md`

## Ownership

- Product context: Product Owner.
- Technical context: Tech Lead and Architect.
- Release context: Orchestrator and QA.
- Context-map maintenance: Context Agent.

## Lifecycle

- Draft: proposed context update.
- Active: approved and used by workflows.
- Superseded: replaced by newer approved context.
- Archived: retained for traceability only.
