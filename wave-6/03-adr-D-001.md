# Architecture Decision Record D-001

## Metadata

- ADR ID: D-001
- Title: Per-channel attributes are channel-scoped values in the temporal configuration register under a closed key set, with language and library registration read from their registers
- Date: 2026-10-08
- Status: Proposed
- Owners: omn-tech-lead as the accepting owner of the Design Gate under the producer exclusion rule; architect as the producing agent
- Related Work Items: MC-7; technical design package DESIGN-2026-0007; planner tasks T-001, T-013 and T-027; sequencing constraints P-002 and P-003

## Context

- Problem statement: a channel today carries only its platform, language and registration flag, so audience, brand, voice, tone, visual identity, content strategy, schedule and risk profile have no home, and a further channel cannot be brought into being by configuration. The attribute list is the union of the master plan's per-channel list and the owner's decision on channel isolation recorded 2026-10-08.
- Business and technical constraints: C-008 forbids any per-channel value acting as a due time, trigger, route, gate state, refusal, precondition or payee and requires an unrecorded attribute to read as not recorded; C-002 keeps the library-registration precondition unsatisfiable from configuration; C-003 forbids recording any channel's value in the company's own store; C-001 forbids a channel becoming live or routed to; C-015 requires additive change.
- Current architecture baseline: F-002 records the channel register's shape; F-003 records the temporal configuration register, its history and the store admitting only the six base keys; F-005 records the library registration register and its consumers; F-037 records the delivered closed key sets with their forbidden-fragment rules; F-004 records that no production code writes a channel.

## Decision

- Selected option: O-002.
- Decision statement: audience, brand, voice, tone, visual identity, content strategy, schedule and the channel's own risk notes are values in the temporal configuration register under a closed channel key set declared once beside the delivered key sets, each scoped to one channel by a scope naming its register identifier. The configuration store admits a channel key only under a channel scope. Language is read from the channel register row and library registration from the library registration register, so neither is configuration. A deterministic profile service composes each registered channel's profile; every configured attribute reads recorded, with value, version and validity start, or not recorded, naming the key and scope looked for, and never a default. The key set carries a forbidden-fragment rule refusing any key naming payee, payment, account, registration, condition, approval, gate, refusal, block, publish, dispatch, upload, route, routing, trigger, due, live or enable, and no component other than the profile service reads a channel key. No channel value is recorded by this change.
- Scope of impact: M-009 declares the key set and its rule; M-006 admits it under channel scope; M-010 holds the profile read model; M-019 composes it; M-023 asserts the rule and the single reader.

## Alternatives Considered

1. O-005, the eight configured attributes as nullable typed columns on the channel register row.
- Benefits: typed columns and one read per channel.
- Risks: the row and its domain record change shape, adding a contract change, and an update overwrites the prior value with no history.
- Why not selected: one more contract change than O-002 on the second criterion, and it gives up the temporal register's history.

2. O-001, O-003, O-004, O-006, O-007, O-008 and O-009, the other options of the package evaluation.
- Benefits: each carries this decision unchanged.
- Risks: each differs from O-002 in another design area only.
- Why not selected: none is decided on this record; they are carried so the option set stays whole.

## Consequences

- Positive outcomes expected: a further channel is a register row plus configuration rows, with no source change; every attribute change is versioned with its author and reason; an unrecorded attribute is visibly unrecorded; no per-channel value can reach a control.
- Tradeoffs accepted: attribute values are free text kept verbatim and interpreted by nothing; language stays on the register row rather than in configuration.
- Risks introduced: R-001, a channel key read as a trigger; R-002, a control-reaching key entering the set; R-032, a value parsed as an instruction.

## Validation Plan

- Metrics to monitor:
  - The count of channel keys naming a forbidden fragment; the expected value is zero.
  - The count of types other than the profile service that read a channel key; the expected value is zero.
  - The count of values changed for one channel when another channel's attribute changes; the expected value is zero.
- Verification checkpoints:
  - A round trip over two fixture channels in a throwaway store, changing each attribute on one and reading both.
  - A fixture channel brought into being by register and configuration rows alone, read as not recorded for every attribute never recorded, and the target of zero routed work units.
  - The solution build failing on a seeded channel key naming a control.
- Rollback or reversal conditions:
  - Reversed if the owner's decision on channel isolation is replaced, or if a per-channel value is found acting as a control; the key set and the store's admission are removed together and the register rows remain readable as history.
